# S3D Equipment Part Array: first release design

The command operates on selected `EquipmentComponent` objects or equipment-level `GenericShape` objects belonging to one `Equipment`. It places independent copies under that equipment. It does not explicitly create nozzles, ports, or external relationships; Smart 3D assigns names under its normal rules. The GenericShape path was added after the user confirmed the selected equipment-level shape should be included. The vendor copy constructor failed in the host, so this implementation creates from the source catalog Part and transfers eligible `IJUA*` instance properties. The resulting geometry and relationship behavior remain a host validation item.

The first selected component is the group anchor. Rectangular counts include the original group at index (0,0,0); the anchor's world position is the default base point. Global axes or the equipment's local matrix axes define offsets. Circular placements rotate the whole group's positions around the specified center and normalized axis. A full 360 degrees uses `360/count`; an open angle uses `angle/(count-1)`. With "rotate copies" disabled, each component retains its world orientation.

The `BaseStepCommand` accepts a preselection or starts with an empty SelectSet. Its Fence step lets the user select components inside the command and capture them from the panel; its SmartSketch3D step accepts base/center/axis points. Parameter changes calculate target positions and show a count. Preview uses temporary highlighted line markers, which are cleared and transaction-aborted before creation and on cancellation. Confirm validates the captured sources again, creates every component in one client transaction, then commits once; any exception aborts the transaction. The array math source is linked into the command DLL and compiled separately for local tests; deployment does not depend on a separate Core DLL. The command entry has explicit COM registration metadata.

API evidence: `EquipmentExamples/PlaceEquipmentComponent.vb:21-54` confirms construction under `Equipment`; `AutomationLabs 2016/EqpRotate.vb:8-68` confirms matrix rotation and `ITransform`; `AutomationLabs_CSharp/EqpModCmd.cs:18-128` confirms selection, graphic mouse coordinates, modeless form and client transaction; `AutomationLabs_CSharp/PlaceLineLab.cs:22-106` confirms temporary highlighted `Line3d` graphics. Installed `EquipmentMiddle.dll` metadata confirms `EquipmentComponent.Part`, `SystemParent`, `Origin`, `Matrix` setter, `AccessControl`, and constructors taking part number or `EquipmentComponentPart` with parent `Equipment`.

Host checks remain necessary for catalog instance variants, name rule results, permission behavior, preview appearance, coordinate units, and rollback on a deliberately failing batch.
